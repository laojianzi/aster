Scope: Dependency Dashboard #11 and the existing grouped branch
`renovate/mygo-native-framework`, reused by PR #41 after approval of the exact
Dashboard entry. Both `go.mod` and
`third_party/native-terminal/UPSTREAM.json` must move together. This review does
not establish a second update branch or replace the hosted Renovate queue.

The reviewed Aster baseline is main
`1dfc816fff2653844fe74f587ee645cce823dcd4`. Local preparation started from
`0231bd9654b39d377009e580ffd2f7430304ffb9`; both commits have Git tree
`635d9361324d3c59483b1b6e2700d610940dfef8`. The completed sign-out integration is
therefore included in the reviewed application source. The upstream changes below
provided no evidence that sign-out had to be blocked on its verified 0.4.2
baseline. The dependency update remains a separately qualified change.

## Actual Aster API surface

An AST inventory of the reviewed baseline found 97 production Go files under
`cmd` and `internal`, excluding tests and the generated terminal adapter. They
reference 30 MyGo package-level symbols: application/window creation, native
layout and list/table controls, menus/selects, text inputs, `TextAreaBuffer`,
`TextBuffer`/snapshots, `Painter` and persistent `Services`.

The relevant retained application callbacks are 78 `OnClick` registrations, one
metrics `Draw` registration, one window `OnClosed` callback, and two `OpenURL`
calls for explicit OIDC login/sign-out. The three `Composing` checks protect Find
navigation, schema navigation and sign-out confirmation. The generated terminal
adapter's `Draw`/`HandleInput` and native stream hooks were reviewed separately;
excluding generated files from the application inventory does not exclude the
terminal from qualification.

The root MyGo package and `ui` exported-declaration comparison was performed for
Linux, macOS and Windows amd64, in checked and `mygo_noinspector` configurations.
Each comparison found 1,347 declarations before and 1,404 after, no removed
declarations and no changed existing function signatures. Four existing public
structs gain fields: `InputEvent.PhysicalKey`, `ElementTransition.Animation/Match`,
`Motion.Scale/Rotate`, and `Router.Animation`. Aster has no unkeyed literals of
these four structs. This declaration comparison is a source-compatibility check,
not an ABI, constant-value, runtime-behavior or hardware-compatibility proof.

## Completion still cannot preserve native Undo through external replacement

The core files
[`ui/text_buffer.go`](https://github.com/egoist/mygo/blob/4d7114c4522498f991f7ebcba9edc9af0f820c6a/ui/text_buffer.go),
[`ui/textbuffer_input.go`](https://github.com/egoist/mygo/blob/4d7114c4522498f991f7ebcba9edc9af0f820c6a/ui/textbuffer_input.go),
[`ui/editor_input.go`](https://github.com/egoist/mygo/blob/4d7114c4522498f991f7ebcba9edc9af0f820c6a/ui/editor_input.go)
and `ui/editor_history.go` are unchanged from v0.4.2. `TextBuffer.Replace` publishes
a new external snapshot. On the next synchronization, `syncBuffer` detects a
snapshot different from the editor's published snapshot and calls `loadBuffer`.
`loadBuffer` clears Undo, Redo, the pending input queue and composition state.

Ordinary native typing, paste and selected replacement still preserve native
history; the two added tests exercise those supported operations. They do not
demonstrate a new programmatic completion transaction. An Undo-preserving
completion feature still needs a supported editor transaction API, with explicit
document identity, selection, composition and stale-result semantics. This
upgrade does not supply that API, and the limitation must not be bypassed through
synthetic key input, retained build-scoped handles or a replacement history stack.
